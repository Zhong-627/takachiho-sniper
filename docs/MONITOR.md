# 手機搶位控制台 PWA

架構：獨立搶位 worker 操作 Mac 的 Chrome，控制台透過私有本機 socket 發送控制命令；正式事件 → Node.js 監控服務 → Tailscale Funnel → 手機 PWA。CLI 和前端使用同一份搶位 runner 與獨占鎖，避免重複啟動。填單、最後確認與付款維持在 Mac 原本的瀏覽器完成。

## 設定與開始使用

在專案根目錄執行：

```bash
npm run monitor:setup
npm run monitor:start
```

setup 使用密碼學亂數產生登入密碼，保存至 `.local/monitor-password.txt`，僅將 scrypt 雜湊與 salt 保存至 `.local/monitor-auth.json`。兩檔權限 `0600`，`.local/` 已排除 Git；終端不顯示密碼。不會覆寫已存在的有效登入設定。

`monitor:start` 安裝 `~/Library/LaunchAgents/com.takachiho.monitor.plist` 並啟動目前使用者的 macOS 常駐服務。關閉終端或結束 Codex 工作後仍持續運作，登入 Mac 時會自動啟動；控制台異常退出後，macOS 會重新啟動它。搶位 worker 不會自動重啟，以免重複暫留。服務記錄存放在 `.local/monitor-service.log`，不記錄密碼或搶位個資。

接著執行：

```bash
npm run monitor:funnel
```

命令先確認本機提供的是監控服務，並檢查 Funnel 設定。預設增加 **8443 → 127.0.0.1:4174** 入口；保留現有其他 port，不使用 `funnel reset`。如果 port 已被其他服務占用，命令會停止，請選 443、8443 或 10000 中另一個可用 port。

檢查或停止常駐服務：

```bash
npm run monitor:status
npm run monitor:stop
```

`monitor:stop` 只停止本專案的監控，並停用登入 Mac 時的自動啟動；再次執行 `monitor:start` 會恢復。原本的 `npm run monitor` 保留為前景模式，須保持該終端開啟，不能與同 port 的常駐服務同時執行。

手機開啟命令印出的 HTTPS URL，輸入密碼後登入。iPhone 在 Safari 使用「分享 → 加入主畫面」；Android 可使用瀏覽器的安裝／加入主畫面功能。網頁也可以直接使用，手機無需安裝 Tailscale。

## 選日期、時段與控制搶位

登入後預設開啟「進度」，手機底部固定提供「進度／設定」兩個分頁。進度頁顯示乘船日期、各時段狀態及交接操作；尚未啟動時可按「檢查設定並開始」前往設定。切換分頁會保留未儲存的修改，並在設定分頁標示「未儲存」；事件更新不會打斷編輯或強制切頁。需人工接手的提醒與連線狀態會出現在兩個分頁上方。

在「設定」選擇乘船日期（日本當地日期）、一或兩個日本當地時段，以及各船的本機乘客資料組。第二時段未勾選時收合其欄位；時段須以官方實際提供的場次為準，控制台不把任意合法時間當成可預約場次。只勾一列就只搶該時段，勾兩列則各自搶位、兩個都保留；兩艘船需不同代表人。

設定頁的「排程 · 台灣時間」先顯示摘要，展開後可調整開始查詢、開賣與截止時間。選擇或更換乘船日期後，會依乘船日前 14 天重新帶入三個排程時間，即使先前已手動修改也會更新：

| 排程欄位 | 前端預設規則 | 台灣時間 |
| --- | --- | --- |
| 開始查詢 | 開賣前 7 分鐘 | 07:48 |
| 開賣時間 | 乘船日前 14 天 | 07:55 |
| 監控截止 | 開賣後 2 小時 10 分鐘 | 10:05 |

三欄都可手動調整，修改其中一欄不會連動其他欄；按「重設為預設時間」可依目前乘船日期重新帶入全部預設值。只修改乘船時段、乘客資料組或重新載入已儲存設定時，會保留原排程。上述時間是自訂的前端監控預設值；官方開賣規則仍為乘船日前兩週日本 09:00（台灣 08:00），實際開放以官方為準。

按「儲存設定」後再按「開始搶位」，Mac 確認啟動成功後會切回進度頁。啟動失敗或結果未確認時會保留目前分頁與輸入。啟動前仍檢查日期、排程、代表人、本機個資／mappings 及可見瀏覽器；截止已過期時不會啟動。

| 操作 | 行為 |
| --- | --- |
| 開始搶位 | 在 Mac 啟動獨立 worker 與各時段的瀏覽器，Mac 使用 caffeinate 保持清醒；會嘗試暫留官方船位 |
| 停止查詢，保留頁面 | 在進度頁停止後續自動化；已發出的 hold 仍確認結果，保留原瀏覽器 |
| 交接到 Mac | 對已結束自動化的該時段解除保護，由你在 Mac 填單、確認及付款；另一時段繼續 |
| 結束並關閉瀏覽器 | 位於進度頁「更多操作」，確認後等待已發出的操作結束，再關閉各預約瀏覽器與搶位程序；控制台仍運作 |

worker／瀏覽器開啟期間，日期與時段鎖定。「停止查詢」後不能直接續跑，須先「結束並關閉瀏覽器」，再儲存新設定及啟動。關閉確認綁定開啟確認視窗時的任務，任務已變更時不會關閉新的執行。關閉瀏覽器不代表官方立即釋放暫留船位。控制台重啟會重新連接原 worker，不會重新搶位。

乘客個資仍保存在 `config/config.local.json`。前端只選「船 1／船 2 的本機資料」；目標選擇另外保存至 `.local/control/settings.json`，不覆寫原始個資設定。啟動時產生 0600 權限的本機設定快照，worker 載入後刪除。從控制台選的新目標不會改變 `npm run doctor`／原 CLI 的 local config 目標，請在控制台核對本次設定。

也可在原本的搶位終端啟動，新版 CLI 使用同一份獨占鎖，控制台能連接它：

```bash
caffeinate -dimsu npm run live -- --confirm-reservation-side-effects
```

控制台啟動本身不會搶位，必須按「開始搶位」或執行已授權的 live 命令。Mac、Tailscale 及控制台服務須保持運作；前端啟動的 worker 不依賴原終端。手機離開頁面、切換網路或關閉 PWA，不會停止搶位。Mac 睡眠或斷網時，手機無法取得新狀態；畫面會標示連線中斷，重新開啟後同步最新資料。

## iPhone 推播

iPhone 需 iOS 16.4 以上，先在 Safari「分享 → 加入主畫面」，再從主畫面開啟 PWA 並登入。在「設定」頁點「啟用通知」後允許系統通知，再點「測試通知」確認實際收得到。Web Push 支援關閉 PWA／鎖屏時接收；系統通知與專注模式設定仍影響顯示。[WebKit 官方說明](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)

官方明確確認暫留後，通知會顯示日期、時段與「已暫留，請到 Mac 接手確認付款」，不代表付款或預約完成。即使後續填表改為人工處理，仍保留已確認暫留的證據。每次執行／時段／裝置去重，傳送失敗短期重試；首次監控已存在的暫留紀錄不補發過期成功通知。推播不影響搶位執行。

標準 VAPID 金鑰與裝置訂閱自動建立於 `.local/push/`，權限 0600，服務重啟後仍沿用。不需新增付費推播服務；Mac 必須能連上 Apple／瀏覽器的推播服務。可用環境變數 `TAKACHIHO_PUSH_SUBJECT` 指定有效的 HTTPS 或 mailto 聯絡網址；預設為專案的公開 GitHub 網址。

「停用這台裝置」取消該裝置的訂閱。登出只撤銷登入，不會自動取消已授權的推播。

## 升級與程序狀態待確認

更新套件並重啟控制台，以載入新後端：

```bash
npm ci
npm run monitor:stop
npm run monitor:start
```

更新前已啟動的舊版 live 無法接收控制命令，請先在 Mac 原终端輸入 `q` 結束，再以新版重啟。新 worker 的鎖 `.local/control/reservation-worker.lock` 與 socket 只在明確結束後清除；程序／狀態不明時控制台拒絕再次啟動，不會直接奪走或删除鎖。請先在 Mac 確認沒有仍開啟的搶位程序、預約瀏覽器與未處理船位，再由本機人工處理遺留 lock／socket；不要在搶位中清除它們。

舊搶位紀錄可能在程序退出後仍顯示「資料過期」，服務重啟讀取大檔時也可能暫時重播先前的查詢階段。已過截止、没有暫留／交接／未明結果的歷史紀錄，會再檢查 Mac 是否仍有本專案 CLI 或 worker；確認沒有程序時，不會鎖住新的日期與時段設定。程序檢查失敗、有效 worker、失聯 lock 或未確認啟動仍保留鎖定。

## 狀態意義

每時段獨立顯示等待／預熱、查詢、重試、暫留、人工處理、停止與截止。查詢次數不是成功機率，沒有完成百分比。

- **已暫留／待人工確認付款**：官方客戶頁已就緒，但尚未完成預約。
- **需要人工處理**：可能包含表單、網站異常或人工驗證；詳細診斷與操作仍在 Mac。
- **暫留結果待確認**：回應不明，不能視為成功或自行再次搶位。
- **已交由人工操作**：僅代表 `handoff`，不代表確認或付款完成。
- **資料已過期**：35 秒沒有正式程式心跳；原終端仍可能開著，請回 Mac 檢查。
- **執行已結束**：保留最後狀態供查看，不宣稱目前仍有有效 hold。

頁面區分監控服務連線與搶位程式心跳。CLI 每 10 秒寫入心跳，即使等待開賣或取得船位後停在人工操作終端，也能辨識程序仍在運作。新增版本之前執行的舊 log 沒有心跳，超過新鮮度期限會顯示資料過期。新版本只能監控重新啟動後的程序，不能替既有程序補入心跳。

監控自動選最新的正式 `live` 執行；inspect、rehearsal、full-rehearsal 不會取代它。首次使用若尚無正式紀錄，畫面顯示等待搶位程式。原 CLI 設定自訂 `artifactsDir` 時，監控需指定相同目錄：

```bash
npm run monitor:start -- --artifacts-dir /absolute/path/to/artifacts
```

## 登入與資料範圍

Funnel 的 HTTPS URL 是公共入口，API 仍需登入。Cookie 使用 HttpOnly、Secure、SameSite=Strict，登入有效期最多 30 天；服務重啟會使既有登入失效。登入請求有節流，短時間大量嘗試會暫時受到限制。

PWA 只接收白名單欄位：目標日期、時段、排程、乘客資料組代號、程序識別、按鈕可用狀態、暫留證據、查詢次數、回應時間、重試／截止／心跳時間與固定事件說明。原始 log、檔案路徑、cookie、個資與截圖不提供給前端。所有控制與推播 API 需登入；修改要求相同來源及有界 JSON，不提供任意程式、路徑或 shell 指令。Service Worker 只快取應用外殼，不快取 API、登入請求或搶位狀態；離線時控制停用。

重設密碼後，停止並重新啟動監控服務：

```bash
npm run monitor:setup -- --reset-password
npm run monitor:stop
npm run monitor:start
```

停止監控服務不影響搶位程式。若要關閉這個公開入口，只關閉本專案使用的 port（依實際設定調整）：

```bash
tailscale funnel --https=8443 off
```

不要使用 `tailscale funnel reset`，它會清除其他服務設定。

## 離線演示與自訂 port

```bash
npm run monitor:demo -- --local-http --port 4184
```

在 Mac 開啟 `http://127.0.0.1:4184`。此模式有「演示資料」標記，可試選日期／時段、啟動、停止、交接及結束；約五秒後模擬暫留，只產生模擬狀態，不讀個資、正式搶位紀錄或操作真站，也不發送真實推播。`--local-http` 只允許本機 Host 的 HTTP 登入，不能透過 Funnel 使用。

正式服務需要 HTTPS 登入；預設本機 URL 用於檢查服務是否已啟動，手機請使用 Funnel URL。自訂 port 時兩端需一致：

```bash
npm run monitor:start -- --port 4184
npm run monitor:funnel -- --port 4184 --https-port 10000
```

也可用 `--auth-file` 指定另一份登入設定，但 setup、serve／service-start、funnel 必須使用同一路徑。常駐服務只安裝一份；使用新參數執行 `monitor:start` 會更新本專案的服務設定。

## 驗證

`npm run check` 涵蓋狀態轉換、資料白名單、增量 log、登入／Cookie／節流、控制與推播 API 的登入／來源邊界、選日期及單／雙時段、乘客資料組重配、過期命令、重複啟動鎖、停止保留頁面、各時段交接、SSE、PWA 快取、推播去重／重試及無效訂閱清理。瀏覽器與 worker 驗證使用本機合成資料；推播測試使用假的傳送器，不建立官方船位，也不傳送真實通知。iPhone 鎖屏實際送達須在你的已安裝 PWA 按「測試通知」確認。
